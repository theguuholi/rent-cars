# Fluid RentCars UI implementation plan

**Goal:** Apply the approved softer mockup, make whole car cards navigable, and provide one catalog search across name, brand and category.

**Design:** White navigation, pale canvas, crimson actions, 24px cards, 12px controls, spacious form groups. Reuse Tailwind utilities and existing components. Keep home navigation-only and preserve roles, drafts and error recovery. Mockup photographs are illustrative; do not introduce invented vehicle photos or detail requests per card.

**Architecture:** Add optional `q` to both paginated car endpoints, applying an OR across the three fields before pagination, AND existing filters. Preserve existing URLs and filter contracts. Keep search state in TanStack Router; no client-side filtering of a page. Whole-card links have one concise accessible name and group hover/focus styles, without nested interactive controls.

**Constraints:** English application copy, no new dependencies, no coverage/mutation threshold changes. Brand and category remain free-text refinements because the public API has no complete facet endpoint; never derive incomplete filter options from one result page.

## Review and verification

- Native implementation; independent read-only review found numeric query parsing and a hidden legacy name refinement. Both new tests failed before the fixes and passed after them.
- `make check-web`: 514 scenarios; 719/719 lines and 594/594 branches. Formatting, lint, architecture and build passed.
- Playwright: 33 scenarios passed against the real API on port 18180 and disposable database `rent_cars_fluid_review`, including card image clicks/Enter at 390px and 1440px and general search through the backend.
- Stryker: 100%, 1,980 killed, zero survivors/uncovered, two pre-existing ignored mutants. Full configured scope with incremental reuse of unchanged results; no threshold or exclusion changes.
- API: `./mvnw -B spotless:apply verify` passed with 526 tests, zero failures/errors, including PostgreSQL integration tests; changed service/controller source lines are fully covered by JaCoCo. Focused PIT was supplementary and is not a claim of 100% Java mutation coverage; other pre-existing mutation gaps remain outside this visual/search task.
- Browser captures updated in `docs/screenshots/rentx-ui/`; screenshots use illustrative fixture data with the real rendered components.
- Deliberate design adaptation: brand/category stay free-text refinements because no public facet API exists. Generic vehicle illustration remains because list responses have no image metadata. No fabricated photographs or per-card detail fetches.
